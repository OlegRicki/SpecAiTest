# SpecAiTest

SpecAiTest превращает локальную спецификацию веб-приложения в сценарии и помогает
написать и проверить браузерные автотесты. Pi исследует интерфейс и создаёт тесты
на Python, pytest и Playwright. Allure сохраняет шаги и диагностику.

## Установка

Нужны Python 3.14, uv, Node.js 22.19+ и npm. Для просмотра HTML-отчёта установите
Allure CLI. Запускайте команды из корня репозитория.

```bash
uv sync --locked
npm ci
uv run playwright install chromium
cp .env.example .env
```

В локальном `.env` задайте `PROJECT`, путь к документу в `DOCUMENT_SOURCE` и
адрес тестового стенда в `BASE_URL`. Если сценарии требуют входа, заполните
`LOGIN` и `PASSWORD`. `HEADLESS=TRUE` запускает браузер без окна.

Для генерации тестов настройте провайдера в Pi и укажите его ID и ID модели
в `LLM_PROVIDER` и `LLM_MODEL`. Встроенные провайдеры используют настройки
авторизации Pi. Для собственного OpenAI-совместимого сервера зарегистрируйте
провайдер и модель в `~/.pi/agent/models.json`. Субагент ПМИ использует
`PMI_MODEL`, `PMI_BASE_URL` и `PMI_API_KEY`; адрес и ключ можно задать общими
`OPENAI_BASE_URL` и `OPENAI_API_KEY`. Для DOCX со скриншотами нужна vision-модель.
Текст требований и изображения выбранного раздела передаются настроенной модели.

## Запуск

Обычный разбор поддерживает Markdown, DOCX и текстовый PDF. Формат описан
в [рекомендациях к спецификации](specs/SPEC_FORMAT.md).

```bash
npm run parse-document
npm run pipeline -- --skip-parse
```

Первая команда готовит `specs/<project>/INDEX.md` и сценарии. Вторая берёт
готовые сценарии, генерирует или обновляет тесты и запускает pytest.
Для одного раздела добавьте `--section` с фрагментом имени файла из INDEX.
Для одного кейса используйте `--case TC-1.1` с ID нужного кейса.

Для ПМИ в DOCX со структурой заголовков, таблицами и скриншотами можно
отдельно запустить нормализатор:

```bash
npm run pmi:normalize -- --list
npm run pmi:normalize -- --section 3.1
```

Замените `3.1` техническим ID из списка. Нормализатор сохраняет сценарий,
исходный фрагмент и журнал обработки. Перед генерацией тестов сверяйте
сценарий с исходником. При вставке заголовка в середину DOCX проверьте
привязки сместившихся разделов: уже сохранённые ID автоматически не мигрируют.
Команда `npm run pipeline -- --pmi --pmi-section 3.1` объединяет нормализацию
выбранного раздела и запуск тестового пайплайна.

```bash
npm run test:py
npm run allure:serve
```

Сгенерированные тесты остаются в `tests/<project>/`. Правила их написания
описаны в [specs/TEST_WRITING.md](specs/TEST_WRITING.md). Документы, тестовые
данные, сценарии, сгенерированные тесты и результаты остаются локальными.
